# تجربة إضافة المنتجات والبحث فيها

هذه تجربة محلية صغيرة في فرع التطوير، وليست نظام إدارة متجر مكتملًا.
افتح `http://127.0.0.1:8001/demo-catalog.html` بعد تشغيل نسخة التطوير.

## طريقة الاستخدام

1. اكتب اسم المنتج وارفع من صورة إلى خمس صور لنفس المنتج.
2. اضغط «إضافة المنتج». يُحفظ المنتج بعد نجاح تجهيز جميع صوره للبحث.
3. ارفع صورة بحث واضغط «بحث في المنتجات المضافة».
4. النتيجة تعرض المنتج مرة واحدة بأفضل صورة مطابقة، مع إمكانية مشاهدة
   باقي صوره. منتجات مختلفة لها نفس الاسم تبقى مستقلة.

## ما يُحفظ وأين

قاعدة مستقلة: `data/demo_store/catalog.db`، تحتوي المنتجات وصور JPEG
وتمثيلات SigLIP2. تبقى البيانات بعد إعادة تشغيل التطبيق. مجلد demo_store
مستثنى من Git، ولا تُرفع صور المنتجات. يُبنى FAISS صغير في الذاكرة من
التمثيلات المحفوظة عند البحث؛ لا يُكتب فوق فهرس الكتالوج الأصلي.
الإضافة ليست تدريبًا للنموذج. حد الصورة 8MB و25 مليون بكسل، ويُتحقق من
جميع الملفات قبل الإضافة. حفظ المنتج والصور عملية SQLite واحدة.

## حدود التجربة

الاسم والصور فقط؛ لا أسعار أو مقاسات أو مخزون أو محلات متعددة أو حسابات
أو صلاحيات. الصفحة تعمل على الخادم المحلي 127.0.0.1. تصميم البحث الحالي
مقصود لكتالوج تجريبي صغير، وليس لاستيراد مجموعة هائلة أو النشر للعامة.
لا يتضمن تعديل المنتجات أو حذفها في هذه المرحلة. مقارنة صورة مضافة بنفسها
تختبر سلامة دورة الإضافة والبحث، ولا تقيس تعميم النموذج أو دقته.

الواجهات المنفصلة:
- GET/POST `/api/demo-catalog/products`
- GET `/api/demo-catalog/images/{image_id}`
- POST `/api/demo-catalog/search`

يُرفض فتح قاعدة البيانات إذا تغير إعداد الترميز المحفوظ بدل خلط تمثيلات
غير متوافقة. لا تُعدّل ملفات JSON أو صور train أو FAISS الخاص بعرض التخرج.

اختبارات الوحدة تغطي استرجاع أفضل صورة لكل منتج، بقاء المنتجات بعد إعادة
فتح القاعدة، فشل الترميز دون حفظ جزئي، رفض المتجهات غير الصالحة، تغيير
إعداد الترميز، تمييز المنتجات ذات الاسم نفسه، وحدود المدخلات.


التحقق المحلي: 94 unittest نجحت، منها 8 لكتالوج التجربة. من المتصفح أُضيفت
سترة بصورتين وفستان بصورة واحدة؛ البحث بصورة السترة من validation أعاد
السترة أولًا والفستان ثانيًا، وكل منتج مرة واحدة. رفض API الصورة غير
الصالحة والاسم الفارغ وtop_k خارج الحدود دون زيادة المنتجات، وأعاد404
للصورة غير الموجودة. مسارات الصور الثلاث أعادت200. الفهرس الأصلي بقي
ببصمة SHA256 السابقة وعدد3068. بيانات هذه التجربة تبقى محلية خارجGit.

بعد إعادة تشغيل خادم التطوير بقي المنتجان وصورهما محفوظين، وأعاد البحث
السترة أولًا مرة أخرى، وعمل التبديل للصورة الثانية من بطاقة النتيجة.
