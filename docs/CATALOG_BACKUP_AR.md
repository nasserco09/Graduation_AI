# نسخ كتالوج المنتجات واسترجاعه

هذه الوظيفة متاحة للأدمن في صفحة إدارة المنتجات. تحفظ منتجات الكتالوج المضاف وصورها وبياناتها وتمثيلاتها للبحث. حساب الإدارة، وكتالوج البحث الأصلي، والنماذج، وسجل البحث مستقلة عن ملف النسخة.

## الاستخدام

1. اضغط **تنزيل نسخة احتياطية** واحتفظ بملف ZIP الناتج.
2. للاسترجاع اختر الملف من **استرجاع نسخة محفوظة**.
3. راجع عدد المنتجات والصور في الملف وفي الكتالوج الحالي. اختيار الملف يفحصه ويعرض المعاينة فقط.
4. **إلغاء** يغلق المعاينة. **استرجاع هذه النسخة** يستبدل المنتجات والصور الحالية بمحتوى النسخة.
5. قبل أي استبدال تُحفظ نسخة تلقائية من الحالة الحالية. تظهر في **نسخ محفوظة تلقائيًا قبل الاسترجاع**، وتبقى بعد تحديث الصفحة وإعادة تشغيل التطبيق.
6. للرجوع، نزّل النسخة السابقة ثم اخترها في الاسترجاع بالطريقة نفسها.

يظهر آخر 20 ملفًا في قائمة النسخ التلقائية؛ لا تُحذف الملفات الأقدم آليًا. حد النسخة 200MB، وتُرفض النسخ التالفة أو غير المتوافقة مع إعدادات البحث الحالية قبل تغيير المنتجات. يحتفظ كل منتج بصوره وترتيبها وسعره وفئته وعملته وحالة توفره.

إذا تغير الكتالوج في نافذة أخرى بعد المعاينة، يُرفض التأكيد وتحتاج معاينة جديدة. كذلك تنتهي المعاينة بعد عشر دقائق أو بعد إعادة تشغيل الخادم؛ وهي مرتبطة بجلسة الأدمن التي رفعت الملف.

## التنفيذ والتحقق

الأرشيف يحتوي JSON وصور JPEG ومتجهات float32، مع بصمات لكل صورة ومتجه وإصدار للبنية وإعدادات التشفير. لا يُفتح ملف SQLite مرفوع ولا يُستخرج ZIP إلى نظام الملفات. تُفحص حدود الحجم، وأسماء الأعضاء، والتكرار، والحقول، والعلاقات، والصور، والمتجهات وترتيبها.

يحدث الاسترجاع داخل معاملة SQLite واحدة بعد كتابة النسخة السابقة إلى القرص. فشل التحقق أو حفظ النسخة السابقة أو إدخال بيانات الاسترجاع يحافظ على بيانات الكتالوج الحالية. ترتفع أرقام مراجعة المنتجات لمنع محرر قديم من الكتابة بعد الاسترجاع، حتى إذا استُرجع كتالوج فارغ ثم أعيد منتج سابق.

تُكتب صور البيانات القديمة ذات ترتيب `0,0` بترتيب عرض متسلسل داخل الأرشيف، دون تغيير قاعدة المصدر. يمنع ترقيم طلبات المعاينة أن يلغي اكتمال ملف قديم وبطيء معاينة ملف اختير بعده.

مسارات الإدارة المحمية:

| العملية | المسار |
|---|---|
| تنزيل نسخة | `GET /api/demo-catalog/products/backup` |
| قائمة النسخ التلقائية | `GET /api/demo-catalog/products/backups` |
| فحص ملف ومعاينته | `POST /api/demo-catalog/products/restore/preview`، ملف multipart باسم `backup` |
| تأكيد الاسترجاع | `POST /api/demo-catalog/products/restore`، JSON يحتوي `token` |
| تنزيل نسخة سابقة | `GET /api/demo-catalog/products/recovery/{id}` |

كلها تتطلب جلسة أدمن. طلبات POST تتطلب CSRF وأصلًا موافقًا. تُحفظ النسخ التلقائية محليًا تحت `data/demo_store/backups/`، خارج Git.

شملت الاختبارات النقل إلى قاعدة فارغة، واستعادة الأسعار والصور والمتجهات والترتيب، والرجوع عبر النسخة التلقائية، ورفض المحرر أو المعاينة القديمة، وسباق المعاينات، والملفات غير السليمة، وفشل القرص أو SQL، والصلاحيات. نجحت تجربة المتصفح بكتالوج اختبار مستقل: تنزيل، ومعاينة، وإلغاء، واسترجاع من منتجين إلى منتج، ثم الرجوع إلى المنتجين من النسخة التلقائية. جُرّب تصدير الكتالوج الفعلي والتحقق من ملفه دون استرجاعه أو تغيير منتجات المستخدم.

الأدلة المحلية في `evaluation/cache/presentation_rc9/`، بما فيها النسخة السابقة لبيانات العرض والتطوير. هذه فحوص إدارة بيانات، وليست قياس دقة بحث.
