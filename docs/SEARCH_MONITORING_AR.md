# مراقبة البحث وتحليل ملاحظات المستخدم

## الهدف

تسجل هذه المرحلة أداء البحث الحقيقي بدل الاعتماد على الانطباع. يحصل كل بحث على رقم عشوائي، ثم يستطيع المستخدم تحديد المنتج الصحيح أو الإبلاغ عن عدم وجوده أو عن خطأ الفئة.

## البيانات المحفوظة

- رقم عشوائي لعملية البحث.
- بصمة رقمية أحادية الاتجاه لملف الاستعلام.
- طريقة البحث: صورة كاملة أو تحديد ذكي أو مستطيل أو مضلع أو رسم حر.
- الفئة المطلوبة والمتوقعة والمطبقة ودرجة الثقة.
- أرقام المنتجات المرتبة ودرجات التشابه.
- زمن البحث وعدد النتائج وإصدارات النموذج والمعالجة.
- تقييم المستخدم للنتيجة.

## البيانات غير المحفوظة

- صورة المستخدم أو النسخة المقصوصة منها.
- اسم المستخدم أو بريده أو رقم جهازه.
- عنوان الشبكة أو أي تعريف شخصي.

تحفظ البيانات محليًا في الملف التالي، وهو مستبعد من مستودع الشفرة:

```text
data/search_observability.db
```

## طريقة إدخال الملاحظة

- إذا كان أحد المنتجات هو المنتج نفسه، يضغط المستخدم «هذه المطابقة صحيحة» داخل بطاقته.
- إذا لم يظهر المنتج، يضغط «المنتج غير موجود».
- إذا كانت الفئة خاطئة، يختار الفئة الصحيحة من قائمة نوع القطعة ثم يضغط «الفئة المتوقعة خاطئة».

يمكن تعديل الملاحظة لنفس البحث، وتبقى آخر ملاحظة هي المعتمدة.

## عرض الملخص

يفتح الرابط التالي ملخصًا رقميًا:

```text
http://127.0.0.1:8000/api/monitoring/summary
```

ويعرض عدد عمليات البحث ونسبة العمليات التي حصلت على تقييم ونسبة المطابقات الصحيحة ومتوسط زمن الاستجابة وتوزيع طرق البحث والفئات المتوقعة.

## استخراج تقرير حالات الفشل

شغّل الأمر التالي من المجلد الرئيسي للمشروع:

```powershell
python -m evaluation.analyze_search_feedback
```

ينتج ملفين:

```text
evaluation/results/search_feedback_analysis.json
evaluation/results/search_feedback_failures.csv
```

يمكن فتح ملف الحالات بصيغة جداول وتحليل الأخطاء حسب طريقة التحديد والفئة والتوقع والنتائج المرتبة، من دون كشف صورة الاستعلام أو بصمتها.

## تفسير النسب

نسبة المطابقات الصحيحة المحسوبة من الملاحظات ليست بديلًا عن مجموعة الاختبار العلمية، لأن المستخدمين قد لا يقيّمون كل عملية بحث. لذلك يجب عرضها كمؤشر استخدام واقعي، مع عرض نسبة تغطية الملاحظات بجانبها.
