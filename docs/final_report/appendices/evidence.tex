\section{Reproduction Commands and Their Meaning}
Run the following commands from the project root using the prepared environment.
Unit tests do not require starting the web service. JavaScript tests use Node.js
for development; Node.js is not an inference-runtime dependency.

\begin{lstlisting}
.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/frontend_selection.test.cjs tests/frontend_demo_catalog.test.cjs tests/frontend_admin_auth.test.cjs tests/frontend_catalog_backup.test.cjs
\end{lstlisting}

The evidence audit checks saved results and current file overlap without running
model inference. The routing command freshly encodes its queries but reuses the
existing original gallery vectors. The smoke command requires an already-running
local service and its fixture; successful searches create normal telemetry in
that service's database.

\begin{lstlisting}
.venv\Scripts\python.exe -m evaluation.audit_evidence
.venv\Scripts\python.exe -m evaluation.compare_category_routing
.venv\Scripts\python.exe tools\smoke_local_app.py --url http://127.0.0.1:8013 --output evaluation/cache/local_smoke.json
\end{lstlisting}

The legacy \texttt{benchmark.py}, \texttt{compare\_sam2.py}, and
\texttt{final\_test.py} scripts can reuse existence-based caches. Running them
without a deliberate cache/provenance protocol is not equivalent to reproducing
the original execution state or measuring a new application baseline. Preserve
the original artifacts when preparing a new controlled study.

\section{Document Production and Editable Materials}
The source document is \path{docs/final_report/main.tex}. Shared names and
environment facts are in \texttt{config/project.tex} and \texttt{config/facts.tex}.
Chapters, diagram sources, appendices, BibTeX records, and the evidence-generation
script are separate editable files. Numeric tables and two vector plots are
generated from the retained results by \texttt{generate\_evidence.py}. The PDF
is built from these sources with numbered, linked citations and automatic lists.

The cover uses the previously approved conceptual artwork and original university
logo. Its illustration was generated with image-generation assistance and is
not a screenshot of the application. Body screenshots were captured from the
actual isolated application during the final-report checks. The composite is
an existing evaluation fixture; its source images are from the clothing dataset.
No screenshot is presented as a newly collected customer photograph or as proof
of aggregate accuracy. Signature and stamp spaces remain blank for the actual
university approval process.
